NO TOCA wr-guides-web ni wr-lab. No agrega secrets ni variables de entorno:
reusa ADMIN_TOKEN y las claves de Supabase que ya existen.

PASOS (en tu máquina)
  1. Descomprimí el zip DENTRO de tu clon de la API, sobreescribiendo:
       cd "<tu-clon>/wr-guides-api"
       unzip -o ruta/al/wr-guides-api-fase8.zip
  2. (Opcional, recomendado) tests de regresión:
       npm install && npm test      → 9 + 17 checks verdes (~1-2 min)
  3. (Opcional) build de control:
       npm run build
  4. Commit + push (Vercel redeploya solo):
       git add -A
       git commit -m "Fase 8: dashboard privado /admin (Basic Auth con ADMIN_TOKEN)"
       git push
  5. Abrí https://wr-guides-api.vercel.app/admin
       → prompt del navegador: usuario "admin", contraseña = tu ADMIN_TOKEN
         (el mismo valor que ya está en Vercel → Settings → Environment Variables)
       → si no lo recordás: es el que generaste con `openssl rand -hex 24`.

VERIFICACIÓN EN PRODUCCIÓN (checklist)
  a. /admin sin credenciales → prompt 401 (nunca contenido).
  b. Con credenciales → KPIs con TUS números reales (vistas/likes acumulados
     desde el 06-10, incluidas tus pruebas y las mías de verificación).
  c. Tabla por guía: los conteos coinciden con los badges 👁/❤ del sitio.
  d. Gráfico de 14 días: barras solo en los días con actividad (el sitio es
     joven: pocos días pintados es lo correcto).
  e. JSON: curl -u admin:TU_ADMIN_TOKEN https://wr-guides-api.vercel.app/api/admin/stats
  f. /api/health y el sitio público siguen abiertos sin auth (el middleware
     solo cubre /admin y /api/admin/*).

SI ALGO FALLA
  · 503 en /admin → falta ADMIN_TOKEN en el proyecto API de Vercel (middleware).
  · Panel con error de BD → la base no tiene la función guide_stats(): corré
    supabase/schema.sql en el SQL Editor (o revisá que el proyecto Supabase
    sea el correcto).
  · El navegador "se queda" con una contraseña vieja tras rotar el token:
    cerrá la pestaña / usá incógnito (Basic Auth se cachea por sesión).
